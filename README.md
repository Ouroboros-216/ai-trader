# AI Trader — 獨立 MT5 AI 操盤代理

中文描述策略 → 檢閱策略卡 → 確認啟動 → AI 定期分析 → MT5 驗證風控並執行。

**Windows 初次設定：解壓縮後雙擊 [開啟設定.cmd](開啟設定.cmd)。** 視窗內填帳號、伺服器，選「模擬／實盤」與 AI API（Gemini 或 OpenAI／GPT），再填該供應商的模型 ID、API key 和飛機 bot token；測試連線，選自己的使用者 ID，按「儲存設定」。視窗也能檢查 MT5、讀取可辨識的券商佣金、啟停 Python 服務與打開完整手冊。第一次會自動建立獨立 Python 環境；設定視窗啟動後 CMD 會關閉。

舊版 `config/local.json`、原資料庫及策略會保留為第一個模擬帳號。設定視窗下方可按「新增帳號」加入其他 MT5 視窗；每個帳號有獨立通訊目錄、資料庫、策略與風控，一個背景服務和飛機 bot 管理全部帳號。金鑰使用 Windows 目前使用者的 DPAPI 加密，存於不打包的 `config/secrets.bin`；須同一 Windows 使用者運行服務。

這是獨立研究系統，不依賴、修改或接管原有 XAU EA。模擬／實盤由各帳號設定選擇；EA 會核對實際 MT5 帳戶類型，競賽帳戶不支援。舊設定預設保持模擬。工程測試不代表交易績效；實際下單仍須在該帳號確認策略與啟動。

## 包含什麼

- 自主 AI 策略解讀、SMC 等文字策略卡及確認流程，版本與記憶存入 SQLite。
- `自動模式` 可讓 AI 根據已有足夠歷史 K 棒的商品提出方法、商品及條件；即使休市或佣金尚未知曉，也可先檢閱草案。交易啟動及新單仍須通過即時報價、成本與風控檢查。
- Gemini 與 OpenAI Responses API 介面：配額預留、限流退避、JSON 驗證、用量與延遲紀錄。OpenAI HTTP 400 只顯示安全的參數／代碼；若模型僅拒絕 JSON 模式，會改以一般文字請求並驗證回覆 JSON。模型 ID 由使用者選擇；切換供應商須在設定視窗操作，不會自動轉到付費 API。
- 自動模式的行情請求只送必要的近期已完成 K 棒；Gemini 503 時逐次延長等待，不連續重送造成額外 API 呼叫。
- Telegram 私人配對、中文命令、提案確認按鈕、只讀問答與成交回報；MT5 面板也有對話輸入框及分頁回覆。
- MT5 多商品 EA、可翻頁面板、獨立帳戶驗證、單商品一倉、初始停損風險預算、日損與回撤鎖定。
- EA 只分析你在 MT5「市場報價」手動顯示的商品；同名不同後綴無法唯一對應時，先請你選擇。
- 提前平倉、收緊停損、兩階段反手；新單暫停時仍可管理已有持倉。
- 程序鎖、原子訊息檔、執行前持久化去重、指令期限、版本與持倉識別碼驗證。
- API 故障時 EA 保護持續；EA 斷線時券商已有停損仍在，但不能保證停損精確成交。
- 帳戶報告、已保存決策的離線介面重播、安裝／編譯／部署／啟停／打包腳本。

Python 3.11+；執行服務使用標準函式庫，無第三方執行依賴。MT5 為 64-bit Windows。多帳號目前須在同一台 Windows、同一使用者的 MT5 Common Files 下；跨 VPS 協同尚未實作。

## 開發驗證

在 `ai-trader` 目錄執行（測試環境需安裝 pytest）：

```powershell
python -m pytest -q
.\scripts\compile.ps1
.\scripts\package.ps1
```

交付包在 `dist/AITrader-v0.8.9.zip`，附 SHA-256。設定視窗儲存時會在 MT5 Common Files 的專用目錄產生帳號綁定；新版 EA 可自動讀取，不必為帳號與伺服器載入 `.set`。初始化參數錯誤時 EA 會彈出具體原因並記錄在 Experts。MT5 面板可送出中文文字並查看回覆；飛機狀態以中文敘述。包內不含設定金鑰、私人 local.json、資料庫或執行紀錄。

設定視窗的「檢查更新」從公開 GitHub Release 取得新版 ZIP 與 SHA-256，校驗後更新程式及這台電腦已安裝的 `MQL5/Experts/AITrader/AITrader.ex5`；帳號、金鑰、交易資料及 Python 環境留在原處。若服務原本在運行，更新程序會停機後重啟。更新日誌在 `runtime/update.log`。更新後須在每個 MT5 終端機重新掛載 EA；舊版 EA 仍在記憶體中運行時，服務會停止新單。

## 常用訊息

多帳號飛機先傳 `帳號`，可點中文帳號按鈕或直接傳帳號數字；選取後會顯示中文操作按鈕與「返回帳號清單」。返回只清除對話所選帳號，不停止服務或交易。提案確認按鈕會綁定原帳號；切換帳號不會把確認套用到另一帳號。

```text
自動模式               （AI 先提出方法與商品，確認策略卡後再啟動）
自動模式 每筆風險0.3%   （可指定低於目前 0.5% 上限的風險）
策略 用 SMC 分析黃金與 EURUSD，只做空，以 M15 進場、H1 和 H4 確認背景。
確認 <提案ID>          （或按 Telegram／MT5 確認按鈕）
啟動                   （另一次確認後才開始新單）
狀態
持倉
原因
為什麼黃金沒有進場？   （只讀查詢，會使用 API）
暫停
平倉                   （提出平掉本系統持倉的提案）
重設回撤               （必須無本系統持倉，再確認）
```

一般自由文字只作查詢；`自動模式`、單獨的風險百分比和 `策略 ` 會建立待確認草案，不會直接修改交易規則。飛機首次策略草案最多等待一次 API timeout；兩次 AI 呼叫至少間隔設定秒數，太快會明確拒絕。

飛機或 MT5 面板可直接輸入 `自動模式`；不寫方法時，AI 會分析 EA 目前已取得、至少有 20 根 M15 與 H1 已完成 K 棒的商品，提出有具體進出場規則的策略卡。H4 歷史資料若尚未載入，草案會如實顯示缺少資料。只傳 `風險0.3%` 也會建立自動草案；百分比視為單筆風險。每筆高於 0.5% 會直接拒絕。策略確認後仍需另行 `啟動`，已確認的策略不會因後續分析自行改版。

飛機傳 `策略全部 用 SMC，只做空……`，檢查全部帳號草案與各帳號商品、風險後按「確認套用全部策略」。確認後各帳號仍暫停新單；逐一檢查狀態，再個別「啟動」及確認。AI 按每個帳號的即時點差、佣金、滑價設定和近期券商呼叫耗時／拒單紀錄判斷；EA 各自計算手數與保證金並執行風控，不跨帳號複製交易。

設定視窗帳號下拉清單會顯示「券商伺服器｜帳號」，實盤另標「實盤」。帳號下拉清單旁有「移除帳號」。先停止服務並從該帳號 MT5 圖表卸下 EA；系統核對無本系統持倉與待執行指令後，將帳號從服務清單移除。原設定檔與交易資料庫保留供核對；至少須保留一個帳號。

## 第一版限制

- 風險只能在硬上限內調整：單筆 0.5%、總初始風險 1.5%、日損 2%、總回撤 5%。不支援用聊天要求 10% 風險。
- 尚無外部新聞、自訂指標檔、圖像判讀、學習權重更新、其他供應商 adapter 或多帳戶 Master/Node。
- AI 實際能否有效解讀 SMC，要由決策紀錄和績效驗證；程式不保證其分析正確。
- 帳戶應專用，不要同帳戶人工加減本系統倉位。淨額帳戶合併交易可能改變持倉歸屬；其他交易仍影響帳戶權益門檻。
- 固定 5 分鐘是分析目標頻率，不是免費額度保證。預設每日最多 100 次（包括策略與問答），不足全天每 5 分鐘分析；請依 AI Studio 配額調低頻率或提高本地限額。限流時不切換付費。
- `replay` 只重驗已保存決策的契約，不模擬歷史成交，不等於績效回測。本版 EA 不在 Strategy Tester 啟用網路代理流程。
